## 1. 頁面角色與版型

| 角色 | 深／淺 | 版型（`deck_helpers.js`） | 一頁只放 |
|---|---|---|---|
| 封面 | 深 | `darkSlide(null, { chrome: false })` | 主題、副標、講者、日期 |
| 今天帶走什麼 | 淺 | 三張 `card` | 聽眾的 2–3 個收穫 |
| 章節頁（長分享才用） | 深 | `darkSlide("第二部分")` + 大標 | 一個段落名稱 |
| 為什麼要在意 | 淺 | 左圖右 `bullets` | 一個工程現象或問題 |
| 心智模型 🎬 | 淺 | 左 `video` 右 2–3 行步驟 | 一個機制 |
| 總概念 | 淺 | 三張 `card` 或一個公式 | 一個定義或公式 |
| 比較 | 淺 | `table` + `source` | 一張比較表，最多 5 列 |
| 數據／曲線 | 淺 | `addChart` + `illustrative` 或 `source` | 一張圖、一個結論 |
| 設計要點 | 淺 | `card` 或 `bullets` | 3–4 條 |
| 常見誤判 🎬 | 淺 | 左 `video` 右「❌／✅」三組 | 三個誤判 |
| 回去可以用（檢查清單） | 深 | 大字清單 | 3–6 條可勾選的項目 |
| 帶走一句話 | 深 | 大字 | 一句話 |
| Q&A ＋ 參考資料 | 淺 | `bullets` | 文件名稱與連結 |

每頁的標題寫成一句結論（「偏心越大，角度誤差越大」），不要只寫名詞（「角度誤差」）。工程聽眾看標題就知道這頁的結論，後面才會去看圖。

## 2. 依聽眾調整

| 聽眾 | 調整 |
|---|---|
| 同領域 RD | 公式和規格可以直接出現；多放設計要點、陷阱、實測數據 |
| 跨部門（ME／EE／韌體／品保） | 每個術語第一次出現就解釋；公式改成文字關係；多講「這跟你的工作有什麼關係」 |
| 新人 | 多一頁「名詞對照」；🎬 頁放慢，每段 20–25 秒；檢查清單寫得更具體 |
| PM／主管 | 原理只留一頁，加上影響（成本、時程、風險）；檢查清單改成決策建議 |

## 3. 🎬 動畫候選清單（依領域）

挑「變化本身就是重點」的機制。下面是常見題材，可以直接拿來發想：

**電子／電路**
- 上電時序：各組電源依序升起、Reset 釋放
- I²C／SPI／UART 的一個傳輸：時脈與資料線逐位元變化
- 電流回流路徑：高頻時回流貼著訊號線下方走
- PDN：負載電流跳變 → 壓降 → 去耦電容補電
- 傳輸線反射：阻抗不匹配時波形來回反射、振鈴
- ESD 放電路徑：電流經過 TVS 流到地，而不是流進 IC

**感測器與物理機制**
- TMR／GMR：自由層轉動、電阻變化
- 霍爾效應：載子受洛倫茲力偏移、產生霍爾電壓
- 電容式感測：電極間電場被手指改變
- 熱傳導：熱源 → 導熱墊 → 外殼，溫度分布逐漸擴散

**機構／材料**
- 公差疊加：多個尺寸的誤差累積成總誤差
- 密封圈壓縮量：組裝時壓縮、間隙封住
- 應力集中：受力時應力在圓角或孔邊集中
- 疲勞裂紋：循環負載下裂紋逐步擴展

**測試驗證**
- IP 等級測試：噴水角度、時間、浸水深度的流程
- 溫度循環：高低溫切換與焊點受力
- 跌落測試：落地瞬間的受力方向

**誤判翻轉**（每份最多一段）
- 「以為是 A → 打叉 → 其實是 B」，三組，翻牌或劃掉的方式

## 4. 動畫一格的節奏

工程機制動畫常見的節奏（15–25 秒）：

1. **0–3 秒**：畫出靜態結構（元件、座標軸、標籤），讓觀眾先看懂「這是什麼」。
2. **3–15 秒**：讓一個變數改變（角度、時間、電流），其他東西跟著反應。一次只動一個變數。
3. **15 秒以後**：停在結論畫面，把結論寫成一行字放在畫面上，至少靜止 1 秒。

參數掃描（例如氣隙變大）可以在畫面一角放一個「目前值」的指示，但標「示意」，不用精確數字。

## 5. 示意圖的畫法

- 右上角放「示意」標籤：簡報用 `D.illustrative(s, 圖的右邊界 x, 圖的上邊界 y)`；影片畫面角落用同樣的字。
- 縱軸用「任意單位（a.u.）」或只標方向箭頭，不放看起來像實測值的刻度數字。
- 形狀要合理：已知是線性、平方、指數、飽和的關係，就畫成那個形狀；不確定形狀時，只畫「上升」「下降」的方向，並在講者備註說明。
- 圖下方用 `D.source(s, "此圖為示意，非實測數據。")`，講者備註也寫一次。
- 有實測數據時，優先用實測，並寫清楚條件（溫度、電壓、樣本數、儀器）。
